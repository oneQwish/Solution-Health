- Все соединения приложения с API Gateway только по TLS 1.2 и выше (предпочтительно 1.3). Незашифрованный HTTP запрещён и в приложении, и на шлюзе.
- Закрепление сертификата (certificate pinning) шлюза в приложении с резервным ключом на случай ротации: так подмену сертификата в сети не принять за настоящий шлюз.
- Токены передаются только в заголовке Authorization, не попадают в адрес запроса и в логи. Персональные и медицинские данные в логах маскируются.
- Взаимный TLS (mTLS) между API Gateway и внутренними сервисами и между сервисами и брокером. Внутрь идентификатор пациента передаёт только шлюз, взяв его из проверенного токена.
- Вызовы внешнего платёжного шлюза и его ответные вызовы (callback) только по TLS. Подлинность callback проверяется подписью (HMAC) и идентификатором платежа.
- Ссылки на файлы результатов анализов временные (подписанные адреса со сроком действия порядка 5 минут), только по HTTPS, а сами файлы в хранилище шифруются.
- Push-уведомления и SMS не содержат медицинских данных, только факт готовности.
- Каналы, по которым передаются персональные и медицинские данные, защищаются по требованиям 152-ФЗ, постановления Правительства № 1119 и приказа ФСТЭК № 21 для уровня защищённости информационной системы персональных данных; уровень определяется при проектировании, и от него зависит, нужны ли сертифицированные средства защиты канала.
