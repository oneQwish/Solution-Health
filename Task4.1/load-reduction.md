Нагрузка на 1С снижается копией базы полисов в сервисе полисов. Сервис держит в своей базе PostgreSQL копию реестра полисов ДМС из 1С: номер полиса, застрахованный пациент, страховая компания, срок действия и статус. Все проверки полиса, и от оркестратора записи, и от API Gateway, выполняются по копии, поэтому число обращений к 1С не зависит от числа пользователей приложения.

Копия обновляется заданием синхронизации. Первый раз переносится весь реестр, дальше задание раз в 5 минут забирает из 1С только изменённые полисы (новые, продлённые, расторгнутые) одним пакетным запросом через HTTP-шлюз. Для 1С это один запрос в несколько минут вместо запроса на каждую проверку. Раз в сутки ночью копия полностью сверяется с 1С, чтобы найти пропущенные изменения. Если 1С недоступна, задание повторяет запрос при следующем запуске, а копия продолжает отвечать; если копия не обновлялась больше часа, оповещаются дежурные.

Онлайн сервис обращается к 1С только в двух случаях: полиса нет в копии (например, полис оформлен несколько минут назад) и прикрепление полиса к пациенту, потому что это изменение данных, а мастер-системой полисов остаётся 1С. После успешного ответа 1С изменение сразу записывается в копию. Онлайн-вызовы идут с тайм-аутом, повтором и circuit breaker по параметрам из `parameters.md`, одинаковые одновременные запросы по одному полису объединяются в один вызов.

Ограничение: копия отстаёт от 1С до 5 минут, и только что расторгнутый полис может ещё пройти проверку. Для записи на приём это приемлемо, интервал синхронизации уточняется с владельцем 1С. Допущение: 1С может отдавать полисы, изменённые после прошлой выгрузки (в 1С для этого есть планы обмена); если нет, задание выгружает полисы с датой изменения позже предыдущего запуска.
